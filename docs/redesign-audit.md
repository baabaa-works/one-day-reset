## 優先清單與順序

1. B：根網址與 #snapshot 統一呈現承諾、開始、信任文案。工作台改為明確點入後繼續；share/friend 及舊 medium=share 都顯示邀請。短參數採白名單，UTM 優先。
2. C：三題 v2、可跳過與可編輯範例、身份句、時間欄；在舊快照物件只新增欄位，保留 answers 陣列與 key。
3. D/E：原話結果、通用卡預設、個人卡明確預覽與確認、一動作 LINE、邀請口吻、圖片網址與全失敗備援。
4. F：保留工作台 state 與全部原節點，只做單題呈現、提醒與六格摘要。新增設定獨立儲存；帶入只填空欄，先列出對應與確認。
5. G/H：本機分類事件、素材、繁中與署名、安全資訊、完整回歸及後截圖。

## 設計與邊界

森林綠 #263b2c、正文 #202b25、淺底 #f0f2e9、紙白 #fffefa、嫩綠 #e3fa9c；沿用本機繁中文字型，無字型請求。手機左對齊、主要動作滿寬、文字輸入至少 16px、互動區至少 44px。不加動畫、框架、後端或付費服務。

首屏：承諾 → 開始 → 免登入與本機信任 → 無 AI 代答 → 次要工作台與來源。結果：原話／身份句 → LINE 邀請 → 可編輯邀請與其他分享 → 私人回答備援 → 工作台。

分享參數衝突依更具體 D 規則：產出 `source=share, medium=friend, campaign=snapshot`；收件入口同時接受 B 的舊 `medium=share`。不對私人文字做 AI 改寫。個人卡只有使用者明確選擇並確認後可匯出；邀請文字與 LINE URL 一律通用且不帶回答。

## B 驗證

首屏／短參數／邀請／舊回答保留 57 項 Playwright 斷言通過；Node analytics 不變量、growth.js 與 analytics.js 語法、diff 檢查通過。`test-results/after-b-{360|390}-entry-{0|1|2}.png` 已視覺檢查。既有完整流程的入口期待值將在後續三題／分享改動後一起更新，H 階段仍須全數通過。

## C 驗證

三題 v2 的任一題跳過、留白結果、兩標籤上限、不代答、起手句可改、身份／時間／步驟暫存、返回、身份結果與空身份退回、私人行動 ICS、兩尺寸無溢出、網址／分析無回答通過。calendar Node 驗證涵蓋日期／時間無效值、午夜跨日、UTF-8 75 octet 折行、跳脫、Asia/Taipei 與實際下載行動文字。快照仍用同 key 與 answers 陣列，只新增 tags、identity、scheduledAt、step。D/E 再補受限下載與記憶體備援。

## D 驗證

21 項分享流程斷言通過：結果直接 LINE、精確 friend UTM、邀請不含回答、編輯與口吻、一鍵複製、Threads 複製備援、通用卡與明確個人卡邊界、未確認禁止匯出、編輯取消確認、PNG 與原生分享模擬、兩尺寸與朋友短網址入口。已檢視圖上的可讀短網址。LINE 格式來自 [官方 Share buttons](https://developers.line.biz/en/docs/line-social-plugins/install-guide/using-line-share-buttons/) 的 url / text 範例，使用自訂文字連結，不載入第三方 plugin script。Threads 官方 web intents 文件無法讀取，未採用未經證實的 intent，採要求允許的複製備援。圖片下載後一律同時提供 img 長按預覽，因瀏覽器無法判定相簿儲存成功。

## E 驗證

Instagram、LINE、Facebook、Threads 四個獨立手機 context，各同時禁止 localStorage（包含讀、寫、移除）、分享、剪貼簿、下載，合計 48 項斷言通過。包含記憶體警語、完成與閱讀、已選取私人回答、手動 JSON、原生分享缺少／拒絕、下載失敗的 img、通用邀請、零外部請求與零 JS 錯誤。`test-results/resilience-{instagram|line|facebook|threads}.png` 保留證據。UA 只用來模擬 App，不決定降級功能。

仍不能由模擬證明實機長按選單與相簿操作成功，也不能證明 LINE 發送或 Threads 發文；下載 click 無法偵測某些 App 的靜默丟棄，因此無論 click 是否拋錯都提供可長按的 img。若連長按存圖也被 App 限制，畫面提示可截圖。
